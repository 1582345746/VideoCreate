# Web 候选构建输入与静态产物一致性

日期：2026-11-14。未发行 dev44 候选 r5；C 盘已安装 dev43 保持原样。

此前候选已记录技能目录的打包源码和归档哈希，但没有强制从当前前端源码重建静态产物，也没有覆盖打包元数据、前端源码和锁文件的输入清单。仅比较归档与静态文件，不能证明静态文件对应当前前端源码。

现在 `tools/build_web_candidate.py` 在新的 F 盘候选目录中执行前端类型检查和构建，逐文件核对 HTML、JS、CSS 的名称、数量和 SHA-256。结果与仓库待打包的静态文件不一致时拒绝构建，不覆盖原静态文件，也不写成功回执。构建前后及打包后再次核对输入，新增、删除或内容变化均须保留当前尝试并使用新目录重建。

r5 回执包含 284 个构建输入的哈希，涵盖技能源码、前端源码、前端/运行依赖锁、打包元数据和构建检查工具；原有 258 个技能打包源码哈希继续保留。还记录 Python、setuptools、build、Node 和 npm 版本。该记录证明输入和构建结果在本次验证中一致，不承诺不同系统或时间生成的 ZIP/wheel 归档字节完全相同。
