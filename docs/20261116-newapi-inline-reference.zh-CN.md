# NewAPI 本地参考直接传输：2026-11-16

本次噜妹妲己项目中，上游 `/v1/assets/review` 已接受两张 PNG 和一段 MP4，但新素材链接及先前成功使用的链接，随后均在无需认证的 GET 中超时。因此不以“上传成功”代替素材可读性检查，不使用未校验链接发起生成。

为履行用户传入实际参考视频的要求，给 `newapi-json-v2` 增加显式 `adapter_options.reference_transport=data-uri`。默认仍为 `https-url`，旧任务、旧路由不变。模式只能用于 NewAPI v2；不会自动降级或切换模型。

直接传输使用实际已登记文件，先检测媒体类型、时长、数量、大小、来源哈希，再于构造请求时重新读取并核对完整字节哈希。发送 `images` / `videos` / `audios` 各类型原顺序的 `data:<mime>;base64,<bytes>`。本机额外限制未编码总大小 32 MiB；上游独立限制仍由该 binding 约束。源码新增 `adapters/inline_media.py`，最小改动涉及 NewAPI adapter、任务预检和配置选项 schema。

预览和任务回执仅保存哈希、媒体属性、模式及协议参数，不保存 Base64 内容。上游回显及错误里的数据 URI 脱敏。已受理任务沿用原 task ID 读取恢复；未知提交仍保持暂停核对，不自动再 POST。不能把本地模拟测试称为上游 Base64 成功，线上状态由项目真实执行回执单独记录。

依据：本地保存的算力AI `/docs?lite=1`，精确型号“稳定高速sd2.5(30参任选/4-30秒/720P)”单独说明，明确素材链接/无后缀链接/Base64 自动补格式；用户此前给出的参考视频下载错误亦明确允许 `data:<类型>;base64,<内容>`。对其他型号不得仅由名称推断相同能力。
