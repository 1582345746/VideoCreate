# 目录检查失败后继续使用已有明确文档

日期：2026-11-14。对应 W10/W14。候选 r15，仍为未发行 dev44；原 C 盘 dev43 安装和配置不变。

## 问题与修复

此前 `Checks.read()` 在目录鉴权失败、404、重定向、超时或凭据不可读时提前返回错误结果，没有附带已有合同列表。页面用这份结果替换当前观察后，原本可见的“按此文档整理接入”随之消失。点击“查看本机记录”能重新找回文档，但这破坏了“没有目录也能依据已有明确文档整理”的直接流程。

现在失败结果仍保留错误原因，返回空目录行和与**当前精确上游地址**匹配的既有文档，不伪造目录观察或观察编号。合同整理继续走原预览/提交，不追加目录读取、不创建媒体，也不因此扩大合同范围。内置配方仍只有 `https://xingapi.top/v1` 的 `seedance2.5-V` 文生视频；其他型号、操作和地址没有新增推定。

成功和失败结果统一重新核对配置来源。检查期间地址、账户变化，或配置被删除/破坏/变成无效时，返回 409 并要求刷新。仅显示名称变化仍可返回同一地址合同；有效归档后的上游不再提供整理配方。已保存的配置和凭据不因目录失败回滚。
