# 参考视频换角色制作：能力审计与完善计划

日期：2026-11-20（Asia/Shanghai）。本轮为离线分析，未提交生成、未查询上游或余额、未修改产品源码/本机配置/已有项目。保留全部历史成片和未提交修改。

## 结论

当前 VideoCreate 可以完成“带角色图和动作参考的视频生成”，但还不能稳定完成用户真正需要的“原片动作与笑点保留、完整人物替换、背景可选更换、节奏便于后期配音”的制作闭环。需要开发和完善，优先围绕这一常用任务，而非继续扩大配置 Web。

既有底座可以复用：上游与模型选择、参考传输、任务恢复、素材哈希、角色库、动作阶段、剪辑和审核都已有实现。主要问题有三类：已有能力没有贯穿实际制作；缺少专用的参考改编数据与校验；模型本身不能保证身份、多人运动和逐拍跟随。三者必须分别处理，不能只归因于模型或提示词。

用户已经接受过雪地滑倒等具体版本，说明这一工作方式能够产出有用结果；反复重做和本批缺陷也说明稳定性不足。没有足够同条件样本，不能计算可信的整体成功率或宣布某型号最佳。

## 真实需求应怎样定义

这类任务更准确地称为“按参考动作重新拍摄”，不同项目有不同的保留要求：

| 模式 | 必须保留 | 可以修改 | 不能混淆 |
|---|---|---|---|
| 换人物 | 原动作顺序、关键表情和人物关系 | 完整角色外形、经用户指定的衣服 | 不能只给原身体换头 |
| 换人物与场景 | 动作节奏、互动逻辑、接触和运动路径 | 背景美术、光线、道具造型 | 改场景仍要保留站位、通道、支撑和遮挡条件 |
| 舞蹈跟随 | 动作节点、左右方向、舞句、时点 | 身形适配、服装、类似场景 | “跳得像”与“可对原音频节奏”是不同验收等级 |
| 剧情压缩或重写 | 观众理解的因果与笑点 | 时长、部分镜头、补充情节 | 需要单独的时间映射；不能继续声称原速逐拍一致 |

默认沿用会话中已有偏好：主角是噜噜与噜妹原角色；按原图完整替换脸与身体；背景允许变化；无背景音乐，常用无声交付；没有要求时不加前后剧情。具体项目要求优先，例如用户选择30秒一次提交时，不能自动改成两条15秒输出拼接。

## 已经具备的能力及边界

| 能力 | 已有实现/证据 | 仍缺什么 |
|---|---|---|
| 图片＋视频参考 | XingAPI v2 / NewAPI v2 有类型数组、参数预检、来源哈希和传输验证；本批已取得真实输出 | `identity`、`motion`主要是本地角色标记和提示词说明，当前适配器不是原生分层锁定/骨骼重定向/遮罩控制 |
| 参考分析 | 媒体规格、候选切点、抽帧、音量/静音测量、来源和观察记录 | 脚本不会自行理解笑点、辨认全部动作或听懂对白；缺结构化动作节点对照及持续运动验收 |
| 角色复用 | 角色裁剪、资产卡、版本化库、invariants、visual_design、physical_design | 需要把原脸/身形/爪子/头饰和衣服变体贯穿每次请求，避免散落于临时文字 |
| 动作与因果 | story requires/effects、performance、action_phases、timing、contacts、entry/exit state | 本批大量没有用这些字段；缺源视频到目标片的对应关系及多人持续身份设计 |
| 请求与恢复 | 绑定上游与完整task ID、未知提交保护、预算、恢复原任务、下载校验 | 本批部分分块下载/参考验证仍依赖临时脚本替换函数，尚非统一产品入口 |
| 后期与交付 | 修剪、静音、字幕/音轨、时间线、源与派生文件区分 | 临时FFmpeg输出没有总能回到标准时间线/审核链；修改目标时长后的状态一致性需补 |
| 审片 | 七层审核、证据方法、哈希绑定、失败优先、播放页 | 当前批次主要是抽帧＋自定义报告；缺参考和成片的同步对照、动作时间误差和正式反馈复用 |
| 模型比较 | 能力/报价/来源/证据分开保存 | 不能据一次成功、价格或上游菜单名推断动作参考质量；需要按任务类型比较 |

## 本次核查到的具体问题

### 1. 静音被错误地绑定成闭嘴，是明确代码缺陷

`planning/project.py:475` 在没有lines，或mode为mute/ambience时，添加：

> No speech; visible mouths stay closed.

黄土坡片实际编译提示词前面同时要求 `expressive silent mouth openings`。这两个要求同时到达模型，计划校验和creative audit没有拦住。实际成片仍会张嘴，不代表冲突没有影响；无法凭这一个样片量化它造成了多少质量下降。

应分别表达：是否输出音轨、是否生成音乐、是否原生对白、是否保留无声说唱口型、是否要求对指定音频同步。无声舞蹈也不应默认禁止笑、张嘴或正常表情。旧任务保存原编译内容，新计划使用版本明确的新语义。

### 2. 原片与角色参考没有真正拆成可验证的保留规则

现有请求会写“图片管身份，视频管动作”，但视频还携带原猫身体、肉垫、衣服、人数、切镜和场景。当前URL数组协议没有独立的“只提取动作”开关，不能保证模型自行解耦。

因此出现只换头、残留猫肉垫、继承切镜并不等于参考未传到，也不能由上游界面“图生/多参”文字单独诊断。应检查实际请求的模型、图片/视频数组、素材哈希、时间片、提示词，再检查输出。角色替换范围和原片允许保留项应成为正式任务字段。

### 3. 角色描述里有不够可靠的通用猜测

本批初版共用 `short plump torso`、`very short thick limbs`、`about1.7 heads tall`。这些不是从用户原图精确测得的比例，对噜妹衣服和腹部膨胀有误导风险；不能证明这是全部原因。

用户原图明确展示了头、鼻吻、身形、腿部、睡帽与服装。先取完整正面和侧面，再分别声明身份与衣服；头饰可见性也应按镜头明确，不能用一个遮住橘子的帽子同时要求橘子始终清楚。

最新版噜妹修正已使用正面与侧面，腰胯改善但下摆仍蓬、有额外尾巴，说明增加描述不保证模型严格执行。需要把这些偏差记录到角色版本和实际候选审查中，不能自动将失败生成图反过来当新标准。

### 4. 动作节奏多为自由文字，已有结构没有用起来

本次离线复核8个生成版本：全部只有一个shot和一条长action；`timing`、`action_phases`、`contacts`、资产`invariants`均未使用，已附着的reference_profiles为0。原片研究存在于research中，并非从未分析；问题是研究与最终计划之间主要靠人工转写。

例如“0–8秒跟随原舞蹈”不足以检查某次抬手是否提前、转身是否漏了、结尾是否多停了。`action_phases`已有镜头内动作时间，尚缺“原片第几秒对应目标片第几秒、哪个人物、哪个动作、允许误差”这一层。

开发后也不能把提示中的时点当成已生成的精确控制。必须比较返回素材的实际时点。动作时间检查不能只看总时长。

### 5. 多人和道具任务需要持续身份与状态约束

五人群舞开头衣服不一致、人物消失再出现；让路片招手弱；洗澡历史版本有已看见被拿走却继续洗澡、荷叶突然出现或挡脸。它们分别涉及演员身份、可见动作和因果/道具状态。

技能已有casting与状态基础，但需要面向参考改编补全：谁替换谁；角色从哪个区域出现；服装每阶段是否固定；谁暂时被挡住而不是消失；道具何时在何处、谁拿着、什么时候换手；角色何时看见事件并作出反应。不能仅靠“不要闪屏、不要变形”负面提示。

### 6. 当前动画入口偏首帧驱动，与常用直接参考流程不匹配

`animation/pipeline.py:135` 的execution_guard对animation层要求已审核的opening-frame；通用reference-to-video入口能直接接受角色图＋视频。本批走的是后者，没有animation层。这不是“参考视频不能用”，而是两个流程还没统一。

应新增或扩展正式的参考改编路径，明确允许“仅人物图＋视频”，与首帧指导路径并存。图片预览只在用户需要或具体方案有价值时使用，不把每个任务强制变成先收费生图。保留首帧流程现有验收规则，避免为新路线把旧门禁整体删掉。

### 7. 正式审片机制存在，但这批没有接入

8个生成版本有自定义`review/observations.json`，正式`reviews/*.json`记录均为0。已有记录诚实标明静帧限制，没有假造播放通过；但标准CLI无法直接利用这些自定义缺陷。

此外，标准审核层按镜头数和contacts决定是否要求spatial_continuity；本批一镜、无contacts的结构令五人/握绳片都没有自动要求这一层。这是适用条件需要补强的线索：同一镜头的多人也有空间连续性问题，不应只靠填不填contacts决定。

应统一技术完成、内容待验、内容失败、用户采用四类状态。用户“可以”可以记录整体采用，不应自动伪造逐项专业通过。局部静帧足以记录可见缺陷，仍不能用于整段运动通过。

### 8. 临时脚本与产品数据存在脱节

七条脚本依次导入炒饭、四条、摩托车、早期舞蹈脚本，再调用已安装C盘核心；分块参考校验/下载在运行时替换函数。它帮助完成了实际工作，但维护依赖旧项目脚本，不是可移植、可测的统一入口。

粉裙回头精剪已有正确6.5秒文件与剪辑回执，但brief仍为11秒。离线`validate_plan`返回`timeline: retained duration differs from brief.target_seconds`。这是交付元数据同步问题，不代表MP4损坏，也不应靠重新生成修复。

本轮只记录该问题，未修改原项目。后续应通过正式剪辑派生流程同时保存生成时长、选版时长、保留区间和审核失效范围。

## 模型能解决什么，技能能解决什么

- 技能能确保参考没有传错、动作分析没有漏项、原脸标准没有混淆、提示没有显式冲突、时间与费用没有计算错、缺陷没有被冒充通过。
- 技能能把原片关键动作、人物与空间关系写得更清晰，也能优先复用用户已经认可的角色版本和制作方式。
- 模型仍决定实际人物稳定、多人遮挡后的身份、接触物理与表情。文字和参考数组无法保证逐帧运动或固定骨骼。
- 普通视频参考跟随与严格原音频逐拍同步分开验收。后者若长期达不到，应评估明确支持动作/姿态控制的路线；仅在接口确实支持时才实现，不能凭Seedance名称宣称具备。
- 不建议当前默认转向逐帧抠像换脸、复杂3D绑定或全自动动作捕捉。用户允许重建场景与身体；先把常用参考生成流程做可靠。动物短肢和遮挡使人体姿态估计容易误判，自动检测只能辅助。

## 怎样判断开发真正有用

先用已有素材建立六类离线回归样例，不重生旧视频：

| 样例 | 主要验收 |
|---|---|
| 噜妹独舞 | 原图身体比例、腿部可见、无新增尾巴；动作关键时点与参考对照 |
| 噜噜门边手势 | 原脸/头顶橘子/圆爪，不保留猫肉垫；动作顺序与左右方向 |
| 双人炒饭 | 同一锅/勺、唱完转炒饭、另一人继续跳、发现要糊后救场的因果 |
| 雪地滑倒 | 原片全身→失衡出画→空镜→左下大脸入画的时间和景别关系 |
| 洗澡拿衣服 | 是否看见偷衣、衣物去向、荷叶预先存在与低位遮挡、反应顺序 |
| 五人群舞/让路 | 固定演员、衣服、遮挡后重现、招手与通道；多人同镜空间连续性 |

关键指标是角色/动作/逻辑可用率、用户采用率、每条采用版本所需请求数、可用秒数成本和返工原因，而不是测试总数、输出文件数或提示词长度。样本小、审片未完成时只报告逐条事实，不算伪精确排名。

严格节奏任务的允许偏差应按用途设置并记录。例如某动作节点±0.2秒只能作为经认可的目标，不是现有模型保证；逐帧同步不能用这个阈值替代。全片动作验收需连续观察，静帧只能覆盖外形和可见状态。
