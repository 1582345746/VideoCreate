# Web 配置变更后的真实历史身份解析核验

日期：2026-11-14。源码仍为 dev44 候选；已安装 dev43、原配置、凭据和项目文件保持原样。

本次只读扫描 `F:/VideoCreate/projects` 的真实项目和保存修订，在新的 F 盘目录建立配置副本，先替换全部认证对象为测试值。通过 Web 的同一事务执行同名标签、模型资料/价格、图片视频默认、同账户测试换钥和归档，再使用原任务身份解析函数逐条比较前后结果。没有对真实凭据做解密，没有执行任务恢复、轮询、下载或创建，也未改写项目路径。

| --- | --- | --- |
| 项目及保存修订 | 120 个目录，108 份 state；12 个目录尚无 state | 包含修订副本，数量不是独立付费项目数 |
| v3 快照记录 | 130 条均可解析，Web 变更前后合同/账户身份哈希一致 | 包含 68 条有 task ID 的记录、10 条 unknown；不是 130 个独立在线任务 |
| 较早格式的已知任务记录 | 170 条使用平台别名；变更前后均因当前配置存在同平台同型号多账户而拒绝解析 | 保持已有歧义拦截；不能宣称这些任务已经恢复 |
| 原始数据 | 项目/state 输入哈希、真实配置哈希复核不变 | 真实媒体、听审、内容接受状态没有新增结论 |

较早格式的记录没有现代 binding 快照，单凭 `sub2api` 或 `newapi` 不能证明历史任务属于哪一个账户；当前配置同时保存了这些平台的多个 Grok 接入。默认、显示名和创建日期均不足以消除歧义。后续应由 Codex 使用原提交回执、任务查询证据或原始配置备份确认精确账户、URL、远端 ID 和 adapter，再按已有恢复流程处理；未确认前保持原 task 和 unknown，不自动重建，不为消除歧义发送生成请求。

核验工具：[verify_config_web_history.py](../tools/verify_config_web_history.py)。执行证据：`_local/web-history-20261114-r2/result.json`，包括逐记录的前后身份哈希和只读输入清单。该报告证明本机身份解析兼容，不证明远端任务或内容仍然可取。原 73 项产品路线图状态未因此改写。

后续补查了这 170 条记录所在的 18 个目录（含保存修订）下全部有界 JSON/JSONL 证据：80 份 JSON、20 份 JSONL 共 1097 行，输入字节复核不变，无解析失败或超限文件。先前只看直接相邻 `logs` 时为 18 份日志/1093 行；递归检查另覆盖两个嵌套日志及四行记录。五条旧记录有 `upstream_id`、adapter 和 remote ID，但该 upstream 值仍是 `sub2api` 平台别名。上述结构化文件未发现原 URL、账户 ID、binding 快照或外部回执/配置指针，尚不足以迁移任何旧任务。

补查证据为 `_local/web-legacy-identity-evidence-20261114-r1/result.json`，记录输入哈希、字段存在性和任务号哈希，不输出真实任务号、提示词或原始日志。此次未读取 C 盘配置备份、解密凭据、扫描聊天/任意文本/媒体/外部归档或访问上游。因此结论仅限于已检查的项目内结构化证据，不声称原身份从未存在于别处；170 条歧义仍保留，不进行猜测迁移或在线恢复。
