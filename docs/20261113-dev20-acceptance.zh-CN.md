日期：2026-11-13。版本：3.0.0.dev20。继续原 73 项路线图的 E02 与 C03/C06、J03/J04/J07；整体目标保持进行中。

## 问题与结果

此前 `max_concurrent_submissions` 只在创建调用期间占用槽位，任务进入上游队列后即释放，不能限制远端排队/运行中的任务，也不区分创建、轮询和下载的请求频率。dev20 在原任务/预算机制上补上本机共享配额，仍保留原任务恢复和未知提交保护。

| 范围 | 本批行为 |
| --- | --- |
| 配置 | 上游新增可选 `quotas.max_remote_inflight/create_rpm/poll_rpm/download_rpm`，正整数；留空为未配置，原用户值不自动填入 |
| 共享范围 | 相同非空账户 ID 或容量组传递关联，共用最严格限制；归档入口保留。空账户名不会误合并不同上游 |
| 在途 | 由已登记项目的当前/历史 `state.json` 推导；queued/running/submitting/submission_unknown/read_pending 等未确认终态持续占用；本地停止等待不释放，没有自动 TTL |
| 释放 | 明确远端完成/失败或确认未受理后释放；完成后下载失败不再占生成在途，但仍按原任务恢复下载。已确认本地未发送的尝试不占用 |
| 原子提交 | 项目锁内取得配额锁，检查后才预留预算和保存提交意图；网络位于锁外。跨项目、多个 binding、重启及本机其他进程使用同一目录时不能重新获得已占名额 |
| 请求窗口 | 创建准入、轮询 HTTP、下载 HTTP 分开记录持久化 60 秒滑动窗口；系统时钟回拨保留未来事件，不借此重置限制 |
| 限流恢复 | 本地配额失败不发送该次请求；已有任务号与可恢复状态保留，返回等待时间，不重新 POST。下载端点/备用链接的每次显式调用分别计数，自动跳转链按一次调用计 |
| 本地索引 | 记项目位置与已观察占用；任务真相仍来自项目文件。不可读/缺失项目保留已观察占用，恢复原文件后重新推导；没有强制清空未知任务按钮 |
| 界面/CLI | 上游编辑器新增配额表单；“查看共享账户配额”使用已保存策略。`providers quotas --upstream ID [--project PROJECT]` 查看或登记旧项目，零网络、零生成；会更新本地派生缓存 |

创建准入数采取保守计数，后续本地预算或写入失败也可能占用本分钟限速；它不等于已发送请求数或账单。实际费用继续查原账本与上游账单，不从配额记录推算。
