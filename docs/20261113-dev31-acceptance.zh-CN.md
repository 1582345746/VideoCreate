## 实际入口

项目面板新增“继续制作”，CLI 新增 `production continue-local PROJECT`。两者共用 `production_continue`，由当前计划、任务、审核和策略决定下一步，保留已有素材和任务记录。

| 当前步骤 | 实际行为 |
| --- | --- |
| 主题、大纲、剧本、角色、分镜、参考 | 显示本阶段的实际内容、输入哈希和关联编辑器；填写理由后可登记“本阶段计划已核对”，使用已有 checkpoint 服务再次核对内容版本 |
| 仅剪辑、混合素材或本地 GIF 尚无来源 | 提供对应导入、转换或编写任务的入口 |
| 剪辑 | 在后台执行当前已保存时间线的本地渲染 |
| 实际审片 | 导出对应视频或图片/GIF 审片页，由管理器打开；实际观察和审核结果继续通过原有记录服务处理 |
| 交付 | 导出共享交付服务的清单，保留实际审核状态 |
| 生成、未知提交或无效计划 | 显示当前任务、原路线、阻塞或结构错误和明确入口；不通过通用继续按钮派发模型请求 |
| 本地 GIF 配方变化 | 显示具体派生记录，使用明确的 gif-rebuild；不会误调用视频时间线渲染 |

CLI 描述是只读操作；只有描述标记 executable 的本地动作才能使用 `--execute --token <返回值>` 执行。Token 绑定本次读取的计划、任务状态、审核状态和输出名；下一步发生变化时拒绝旧决定，要求重新读取。管理器每次点击重新描述，后台执行一个本地动作。

此检查在动作开始时进行，不是跨 FFmpeg 的长期项目锁，也不提供文件系统不可变快照。执行后的并行编辑仍按已有渲染清单与审核规则使旧产物过期。创作核对仅核对计划，不批准媒体；自动推进策略不授予花费授权。动画 sidecar 的故事、导演和生成源不交给普通编辑器覆盖，本地 GIF 保留配方服务。
