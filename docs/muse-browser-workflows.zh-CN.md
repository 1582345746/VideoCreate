# Muse 浏览器工作流接入

## 需求与边界

VideoCreate 保留现有 API 生图、生视频路线，新增可组合的浏览器生成阶段。模型（Grok、Seedance 等）、API 上游（Sub2API、NewAPI 等）与浏览器站点是不同概念；Muse 不使用猜测出的 API 地址或模型 ID。

统一使用 `videocreate.config.json`：API 继续使用 `models/upstreams/bindings/routes`；网页服务使用 `browser_services`；组合方式使用 `workflows`。剧本、分镜、素材哈希、剪辑和内容验收继续复用。

| 需求 | 阶段顺序 | 本次交付范围 |
| --- | --- | --- |
| 原有路线 | API 生图 → API 图生视频 | 原运行器继续可用 |
| Muse 生图 | Muse 文生图 | 配置校验、交接包、技能操作流程 |
| Muse 文生视频 | Muse 文生视频 | 配置校验、当前镜提示词交接包 |
| Muse 图生视频 | Muse 生图 → Muse 图生视频 | 阶段依赖校验、素材交接 |
| 混合路线 | API 生图 → Muse 图生视频 | 复用独立图片生成和素材登记 |

`workflows` 是可执行阶段的描述和交接入口，当前没有自动串行执行整个网页工作流的无人值守运行器。离线准备不点击网站，也不创建付费任务。

## 浏览器选择

优先使用用户指定的内置浏览器。打开页面工具不等于读取、点击、输入、上传、下载工具。先核对当轮实际接口；没有操作接口时报告 `browser_tools_required`，不得宣称自动化测试通过。

独立 Playwright 浏览器只能在用户选择该方式后使用。它的专用会话不与内置浏览器共享；不导出、拷贝或探查内置浏览器 cookies。密码、验证码由用户手动输入。用户配置只保存站点和驱动选择，不保存认证会话。

## 2026-11-02 实测记录

- 已在内置浏览器读取 `https://muse.ai/` 的已登录聊天页，页面标题为 `Chat — Muse`；当前会话的聊天输入和附件按钮可读可操作。
- 通过一条明确要求“只做能力查询，不要生成、不要上传”的消息，页面返回并列出了文生图、图生图/图片编辑、文生视频和图生视频均可用。页面没有模型、分辨率或精确时长选择控件；视频约 10 秒。
- 同一会话历史中的两条结果实际显示为 1280×720（16:9）和 720×1280（9:16），均为 720p；此前要求 15 秒和 12 秒时页面返回 10 秒。该历史结果是页面证据，不代表本轮重新生成。
- 账号只显示总体免费周额度已用 5%，没有给出单次图片或视频的消耗数字；因此费用仍需在每次生成前现场核对。
- 本轮没有上传文件、点击生成或下载产物，没有发生本测试触发的生成扣费。能力已查询，真实生成、任务 ID、下载和内容验收仍未完成。
- 本机页面证据保存在被 Git 忽略的 `analysis-frames/muse-browser-probe/`，不上传账号信息或浏览器配置。

## 现场验收清单

1. 由用户登录并进入真实生成页面，核对最终域名；优先使用当前可读可操作的内置浏览器。
2. 分别核对文生图、文生视频、图生视频入口；记录可见模型、画幅、时长、参考图限制和费用，不从配置反推支持。
3. 用一个简短分镜测试。先记录本地准备包和提交意图，再点击生成一次；保存真实任务 ID/详情页及页面证据。
4. 超时或点击结果不明时保持待核对，不重复提交；页面无记录不足以证明未创建。
5. 下载原始文件，登记哈希和来源；图像检查参考一致性，视频实际观片/听审动作、镜头和叙事。
6. 再验证 API 图片 → Muse 上传 → 视频下载 → VideoCreate 时间线。最后才标记具体操作已经实测通过。

这些现场项依赖真实账号页面和可操作浏览器；目前不能用模拟测试代替通过。
