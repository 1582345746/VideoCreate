# 图片按张预算边界（dev44 候选）

本批扩展 W11 的核心计费语义。Schema 4 图片接入可配置 `pricing.per_image` 和档位内的 `per_image`，单位是请求明确发送的出图张数。所有金额只用于预算估算，实际扣款仍未知；没有发起收费生成或重生样片。

| 情形 | 预算行为 |
| --- | --- |
| 当前 `openai-images-v1` 合同明确发送 `n=1` | 按一张估算 |
| 合同的 `image_request_fields` 不含 `n` | 张数未知；不推定供应商默认值，不强行增加合同外字段 |
| 每请求费 0.01、每张费 0.04，明确一张 | 估算 0.05；明确零费率仍按零处理 |
| 基础与选中档位同时有费率 | 只采用唯一选中档位的费率，不叠加基础费率 |
| 选中档位只有每请求费 | 不要求图片张数；基础每张费已被替代 |
| 档位缺参、无匹配、重叠，价格未核实、未生效、到期或币种不符 | 沿用未知规则；未知金额不能证明硬预算 |
| 视频使用按张价格，或同一价格定义混用秒费、最低/取整秒数、时长档位条件 | 配置校验拒绝 |

参考图数量、GIF 帧数、供应商返回的图片数量均不构成预算张数。Web 筛选/比较的输入不接受用户传入 `image_count`；生成预览、图片计划编译、运行器预算预留和目录报价从图片适配器共用的计数函数获取数量。纯计算函数仍拒绝零、负数、布尔、字符串、非整数或非有限数量。

Web 结构化表单提供基础和档位每张价，与高级 JSON 共用一个模型表单，只有父保存提交配置。恢复草稿保留新费率，不能把丢失字段解释为零。Tk 常用价格和档位编辑也保留新字段，并将旧“每次 / 每张”标签明确为“每请求”。CLI 图片比较省略视频参数；显式传入视频秒数、分辨率或画幅时拒绝。
