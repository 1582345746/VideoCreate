# VideoCreate 整体框架梳理：制作流程、共用模块与底层数据

日期：2026-11-20。状态：框架提案，尚未按此重构。

用户已要求暂缓开发，先整理全貌；目标模式已清除。本文件仅梳理，不执行生成、上游测试或安装。此前落下的声音／嘴部控制源码修改保留在 F 盘，未发布、未安装，不代表下文功能已实现。

## 1. 产品定位与整理结论

VideoCreate 是由 Codex 驱动的本机视频制作技能：理解需求、研究参考、设计角色与表演、调用适合的图像／视频／声音服务、剪辑、审片与局部返工。

目前机器目录有 21 个模块、73 项历史工作包，另有 R01–R14 参考改编专项。旧目录混用了创作能力、上游适配、管理界面与测试职责；这些数量不等于用户需要学习的制作流程数量。目录日期为 2026-11-13，其中部分在线验收说明已滞后于后续实际生成，不能据此断言今天的能力或可用性。

建议整理为：**6 类主要制作流程 + 12 个共用能力模块 + 跨模块的数据与质量规范**。

- 制作流程决定从什么材料出发、要交付什么。
- 声音方案、动作／口型保真要求、单条／系列、单次／分段生成是组合选项。
- 自拍感、真人感、动画、古装、搞笑、广告、快节奏是创作模板与风格，复用相同执行系统。
- 本机 Web 保持上游配置用途：用户主要填写 URL、Key，名称和备注可选。协议、模型和参数由 Codex 根据实际合同维护。
- 本地审片页、分镜阅读稿是项目产物，可以独立打开；不由此扩展上游配置 Web。
- 发布社交平台继续由独立发布技能承担，视频制作以可用成片和交接包为终点。

## 2. 底层首先要分开的概念

### 2.1 参考材料、制作要求、远端结果、审核事实

用户原图定义角色标准；参考视频提供动作和节奏证据；声音样本提供音色／发音／语气线索。剧本写了什么、上游实际收到什么、视频实际生成什么、观众看懂什么，需要分别记录。

“已提交”“已生成”“已下载”“用户采用”“身份通过”“动作通过”“音画同步通过”是不同事实。失败候选不得自动替代原角色标准。

### 2.2 画面动作、可见口型、可听音轨

三者独立指定，再通过时间关系关联：

1. 画面动作：抬手、扭头、跳舞、抓握、出画等。
2. 可见口型：自然表情、说唱表演、对指定台词／音频同步。
3. 可听音轨：对白、旁白、环境音、音效、音乐以及最终静音。

因此无声视频可以保留完整说话口型；不要音乐可以保留对白；有参考音频不代表必须把该音轨放进最终文件。根据模型能力，可以在制作阶段生成同步对白视频，再导出无声交付版；这个选择必须明确记录，不能让最终静音要求提前抹掉说话表演。

### 2.3 四个时间坐标

必须关联参考原片时间、提取音频的时间、生成素材时间和成片时间。裁掉原片前 3 秒后，音频第 0 秒对应的是原片第 3 秒；剪辑后又可能发生变化。

严格对口型时优先保持原音频时序；舞蹈配原声时保持舞句与动作节点。压缩剧情、删除片段或变速时重新建立映射，不能继续声称和原声整段直接对齐。

### 2.4 事件、镜头、请求、候选、剪辑片段

一个事件可以有多个镜头；一个生成请求可以包含多个场景；一次请求可以提交多张图片和多个视频／音频参考。参考文件数量、场景数量都不等于收费请求数量。

“30 秒、一次完整生成”明确约束为一个 30 秒生成任务；不能自动替换成两次 15 秒。用户允许分段时，才规划多个任务及其衔接。

## 3. 六类主要制作流程

| 流程 | 适用需求 | 主要路径 |
|---|---|---|
| W1 原创视频 | 一句话创意、搞笑短片、短剧、广告、场景展示 | 明确观众看到什么 → 剧本与因果 → 角色／场景 → 分镜与表演 → 按需生图 → 生视频 → 后期与审片 |
| W2 参考视频改编／换角色 | 原猫狗换噜噜和噜妹；动作、节奏、笑点保留，背景或衣服可换 | 参考研究 → 保留／替换表 → 演员对应 → 原片到目标时间映射 → 角色图＋动作视频＋按需音频 → 生成 → 同步对照审片 |
| W3 图片驱动表演 | 一张人物图跳舞、表情、商品或场景动起来 | 身份／构图核实 → 动作与摄影设计 → 可选动作参考 → 图生／多参生成 → 审片；无须强制编完整故事 |
| W4 有来源的科普／新闻／历史说明 | 基于资料说明事实、技术、地理或事件 | 来源与主张 → 讲解逻辑 → 旁白与画面分工 → 实拍素材／生成示意 → 字幕、地图与标注 → 事实和成片双审 |
| W5 已有素材剪辑／混合制作 | 静音、剪辑、配音配乐、字幕、修补某一镜、已有片加生成镜头 | 导入真实素材 → 时间线 → 识别缺镜 → 仅按需补生成 → 声画后期 → 派生成片审查 |
| W6 图片／角色设计／GIF | 定妆图、衣服场景预览、高清图、独立图片、动图 | 图片／设计要求 → 生图或编辑 → 身份与细节审核 → 图片交付或进入视频流程；GIF 区分原生生成与本地转换 |

W1–W6 是推荐入口；一项任务可以有主流程和子流程，例如参考改编先做角色服装预览，再回到 W2。不要另造七套任务恢复、费用和审核系统。

系列是作用于这些流程的跨项目机制：连续剧继承经过验收的上集状态，独立系列只共享角色／声线／世界观，不强制继承上集结尾。舞蹈、搞笑、动作、怀里告状、产品片等保留为模板，不能强迫所有类型使用相同切镜速度或剧情结构。

测试、版本兼容、迁移、打包和诊断是覆盖 M01–M12 的工程保障，不能以配置页面或测试数量代替视频质量验收。

## 5. 参考改编的必备任务表

每条参考改编都明确以下选择，使用已经得到的用户偏好，无需机械地逐项再问：

| 维度 | 可选要求 | 本会话例子 |
|---|---|---|
| 人物身份 | 完整替换／保留；原图与版本 | 单人用噜噜；双人用噜噜和噜妹，不能只换头 |
| 身体与比例 | 按原角色、允许动作适配 | 噜妹不能变胖、凭空长尾巴；噜噜不能保留猫肉垫 |
| 服装与头饰 | 保留／指定改装／可设计 | 粉裙但原脸不化妆；橘子和单片叶子必须露出 |
| 群体关系 | 演员一一对应、相似配角可区分 | 五人群舞、三个噜噜，人数与服装跨阶段持续 |
| 动作 | 风格参考／节点跟随／严格复刻 | 手势顺序、雪地全身到大脸入画、摩托后座险落 |
| 镜头与背景 | 保留／类似／重设计 | 炒饭摊可换背景，仍需两口锅、操作位置与救场路径 |
| 剧情 | 保留／压缩／改写 | 偷衣被看见后立即反应，不能继续毫不知情地洗澡 |
| 时间 | 原速／明确重排；事件到目标秒数 | 30 秒一次生成；不能把两条参考误算成两条输出 |
| 声音与口型 | 按第 6 节组合 | 无音乐对白、无声留口型、参考沙哑声音 |
| 验收 | 哪些必须通过，允许什么变化 | 头饰存在、角色正确、关键动作不漏、原声能对齐 |

快节奏应由动作节点、信息变化与长短镜头设计体现；“快一点”不能替代原片动作时间表，也不意味着所有视频都要频繁切镜。

## 6. 声音版本与音画同步

### 6.1 用户选择的交付版本

| 交付版本 | 画面／口型 | 最终声音 |
|---|---|---|
| 无声动作版 | 自然表情＋所需动作；不强制闭嘴 | 无音轨，用户后期配乐或配音 |
| 无声对口型版 | 按指定台词／音频时间保留说话口型和动作 | 无音轨，同时保存时间基准与参考音频；不能只做静音通用舞蹈 |
| 对白版 | 对应角色发声，口型与实际台词同步 | 对白为主，音乐、环境音和音效分别选择 |
| 音乐版 | 舞蹈、蒙太奇或剧情按所选节奏设计 | 用户提供音乐、后期选配音乐或明确请求的模型音乐 |
| 对白＋音乐版 | 对白与动作保持同步 | 对白和音乐分别管理、混音，音乐不能掩盖对白 |

“自己配乐”是后期职责选择，可以交付无声版，也可以交付保留对白、无背景音乐版。旁白型视频不需要角色跟随旁白张嘴。环境音和拟音也独立控制。

### 6.2 声音来源与复刻目标

声音来源有模型原生生成、参考人物声音、独立配音服务、用户提供成品音频、原片授权采用音轨等。复刻声音还要区别：音色相似、方言／发音、语速／情绪／停顿、同一句话及其原始时间。这些不是同一种保证。

用户明确要求：需要复刻声音时，从视频提取声音，再发送给上游作为音频参考。推荐完整路径：

1. 保存原片哈希、目标人物及对白起止时间。
2. 提取实际音轨；按人物和对白段裁切。
3. 若有人声和音乐混合，走分离人声分支；若没有分离工具，明确缺口，不把提取混音声轨冒称纯对白。
4. 听审清晰度、残留伴奏、分离伪影、人物归属和语速；ASR 可辅助文本，不能代替听审。
5. 保存音频哈希、原片对应区间、文本／方言／音色目标与角色关系。
6. 在真实支持该组合的 binding 上发送：角色图片→身份；参考视频→动作／摄影；提取或分离后的音频→声音／说话节奏。记录实际数组与参数消费。
7. 对返回视频听审音色与台词，核对口型和动作节点；按要求导出对白版或无声版。

仅把 MP4 转成 WAV 不会去掉背景音乐。人声分离也不保证完全干净。去音乐不是普通 `mute`，因为 mute 会连对白一起去掉。不要通过加速音频掩盖视频口型中途停顿。

### 6.3 精度目标需要拆开

| 目标 | 含义 | 必须检查 |
|---|---|---|
| 风格相似 | 相似舞蹈、口音、表演情绪 | 观感、人物、动作与语言风格 |
| 事件／节奏跟随 | 动作次序与关键节点按目标时间发生 | 原片／成片对应事件、偏差、左右方向、停顿 |
| 指定音频对口型 | 按同一音频的说话起止、停顿和可见发音同步 | 连续播放与听审，不用抽帧代替 |
| 严格动作复刻 | 姿势、运动轨迹与时序需要更高精度对应 | 实际动作控制能力、人物形体适配和逐段对比 |

动作精度与口型精度分别选择，不能共用一个“严格”开关。当前普通多参考数组已可传入材料，但未建立严格姿态／逐帧控制合同与该类验收证据；不能凭 `seedance2.5-V` 名称或一句提示词承诺。

若用户要求的精度超过现有路线，应显示可满足部分和缺口，再评估支持相应控制的上游或可选本地方案。旧 CosyVoice／Voicebox／MuseTalk 桥接应保留为可选能力；代码入口存在不代表本机依赖已安装，也不代表对噜噜／噜妹等非人脸效果已通过。

## 8. 底层数据沿用什么，缺什么

沿用 `project`、`brief`、`story`、`director`、`generation-plan`、`timeline`、`assets`、`jobs`、`state`、`reviews` 和 `deliverables`。制作阶段状态从这些记录推导，避免临时脚本另存一套互相矛盾的状态。

需要补齐的数据关系，而非立即确定所有新文件名：

- 参考研究：原片哈希、人物、事件、动作／表情／对白区间、证据方法。
- 改编要求：保留／替换维度、优先级、演员对应与角色版本。
- 时间映射：原片／音频／目标素材／最终剪辑的对应，允许误差与被省略事件。
- 声音方案：交付版本、声音来源、说话者、参考用途、音乐来源、生成阶段与最终静音的区别。
- 审核观察：检查目标、实际时间点、通过／失败／未核实、输出哈希与修复建议。
- 经验记录：具体上游／模型／操作／任务类别、同条件标识、请求数、耗时、目录报价与实付、采用版本与可用秒数。

## 9. 当前判断与下一步边界

可复用底座较多，主要欠缺的是参考研究、角色标准、动作／声音要求、实际请求、成片审查之间的贯通。常用项目仍借助临时脚本，是整合优先级高于继续扩大配置界面的依据。

当前已安装版本标签为 dev43；F 盘源码标签为 dev44。它们不代表所有待办分别完成或失败。暂停前只新增了声音／嘴部语义的局部源码改动与专项测试，尚未完成整体回归和发布；本提案没有把计划状态改成完成。

恢复开发前，先以本框架核对原 73 项和 R01–R14，合并重复需求。声音方案应补入“提取音轨／人声分离／角色音频参考／指定音频对口型／无声保留口型／音乐后期”的完整链路。严格动作与口型的路线评估提高为按任务触发的能力缺口处理，不把未证实的能力默认打开。

用户已允许按需要访问上游测试。当前要求是先列框架，因此本次不访问上游；后续测试由具体未知项驱动，区分只读合同检查、传输检查、实际生成和内容验收，每次保留请求范围与结果，避免无目的重复生成。
