## 功能与边界

新增 `mixed-video` 制作分支：本地视频来源与模型生成镜头共用五层计划、时间线、审核、交付和统计。初始计划为空，不虚构镜头、任务或时长。可指定明确成片目标和横竖画布；仅有本地来源时，编译、路由和执行检查均不读取上游配置。

| 入口 | 当前行为 |
| --- | --- |
| `plan init --profile mixed-video` | 创建零任务混合草稿，下一步提示导入来源或创作镜头 |
| `production import-clip` | 保留原文件，完整解码项目副本，登记哈希、真实时长、音轨和保留区间 |
| `production import-clip --shot-id ID` | 对应一个已创作、尚无来源和剪辑的镜头；完整保留其 beat、动作、证据、场景及声音意图 |
| `generation-plan.jobs` | 只保存真正需要上游生成的镜头；本地来源保持在 `local_sources`，不制造假任务或账本条目 |
| `jobs run` | 串行、并发均允许本地来源 ID 作为就绪依赖；原提交恢复、未知保护、选型及预算继续使用现有机制 |
| `production script-export` | 导出剧本和只读来源→时间线映射；结构化剧本导入仍只修改导演层 |
| `production status/impact/metrics/deliver` | 分列本地来源与生成任务；实际保留秒数覆盖两类，模型请求数、生成秒数和费用只计算上游工作 |
| 管理器项目面板 | 混合项目可导入视频，并填写可选的已有镜头 ID；后台复制和解码，不阻塞主窗口 |

本地来源 ID 不能覆盖计划或已保存任务，镜头不能同时由本地来源和生成任务供片。已有镜头映射拒绝替换原来源、任务和时间线片段；不填写 `--shot-id` 时才新建本地镜头。映射的新片段追加到时间线，需明确安排顺序；`--description` 只供新建镜头使用，已有镜头的用途在导演层修改。叙事分支继续要求因果事件链与可见证据覆盖，来源映射本身不证明素材符合剧本。

本地依赖在整批预检和请求准备时校验哈希。失效会阻止创建及预算预留；它表示素材已就绪，不自动上传、不作为模型参考，也不授予内容通过。若模型实际要消费素材，仍需明确的 typed reference。刻意替换为另一份合法来源不会因此自动重生已完成模型视频。最终哈希检查后仍存在文件被外部更改的窗口，尚未使用系统级不可变文件句柄。

审核汇总按当前素材分别校验回执：修改字幕或另一素材的导演合同，不会抹去未变素材的有效观察。最终剪辑仍单独失效，需要重新渲染、实际观看和审核；导入完整回执仍严格验证全部条目。同字节观察到的缺陷继续优先于通过记录。不能把本地导入、结构校验或渲染成功当作内容验收。

本版覆盖本地视频与模型生成视频。每次导入后的全计划仍须通过校验；多个尚未覆盖的已创作镜头尚无批量绑定入口，应逐步创作并导入来源。静态图片时间线、图片生成和视频混排、图形化剧本/时间线编辑、全面多文件断电事务仍待开发。GIF、纯图和仅剪辑分支保持独立。
