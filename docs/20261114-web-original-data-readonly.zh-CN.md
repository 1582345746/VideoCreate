## 如何保持只读

- 测试服务直接调用生产 `create_app(..., read_only=True)`，不用会在配置旁写入实例登记的启动器。本次不把应用工厂验证记成新的启动器验证；四入口证据继续使用 r16 原安装记录。
- Python 测试进程在导入产品之前安装审计钩子：禁止 F 工作区之外的写入、非 loopback 连接及子进程。取钥、私有凭据存储读取和 DPAPI 解密原语另以拒绝函数替代；主线程及工作线程还按原函数代码拦截事先导入的别名。浏览器只允许明确的本机只读接口，禁止目录联网、保存、草稿写入、导出和其他 origin；测试未尝试被禁止的操作。
- 所有日志、截图、临时目录和 Chrome profile 均指定在 F 盘。审计计数针对应用进程；不将其扩大为对 Windows 或 Chrome 系统活动的全面审计。
- 原配置目录前后检查 **32,432 个文件**：32,431 个可读文件逐个 SHA-256 一致，没有新增、删除或变更。`local-media/server-lock/.videocreate-state.lock` 正由原 8765 服务持有 Windows 字节锁，保持服务和锁不动，只核对该锁的大小及修改时间，不声称已核对其内容哈希。

浏览器/API 对照的是原配置的结构、精确接入 ID 和操作；只扫描配置中已有的明文密钥/环境变量名/凭据引用是否意外进入 DTO 或页面，不读取解密后的真实 Key。原 `secrets.dpapi` 仅作不解密的文件哈希核对。
