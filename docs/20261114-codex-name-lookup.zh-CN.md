# Codex 从保存名称查询上游与型号

日期：2026-11-14。源码/候选仍为未发行 dev44，已安装 dev43 保留。本批推进 W19/B02，不改变视频执行或旧任务恢复的身份规则。

用户在 Web 保存可选名称后，Codex 可提取请求中的名称词，调用 `providers identify --kind image|video` 查询同一配置，再把规范 ID 交给既有选择与请求预检。此前把显示名直接传给 `selection.resolve` 会得到空菜单；该入口仍只接受稳定 ID，离线查询单独承担名称查找。

| 用户提供的信息 | 查询参数 | 结果边界 |
| --- | --- | --- |
| 上游和型号 | `--upstream-name` 与 `--model-name` | 两个维度交集，同名不自动选启用账户 |
| 只给上游 | `--upstream-name` | 只列该上游词匹配的媒体接入 |
| 只给型号 | `--model-name` | 精确 ID 或保存名称/家族对应的接入 |
| 两个都不给 | 仅 `--kind` | 列该媒体全部接入，不自动套默认 |

稳定 model/upstream ID 优先于冲突的显示名；否则精确匹配保存的上游名称/platform、remote_model、binding/model 名称或已配置 family。大小写、空格不规范化，不作句子解析、子串、同义词或任意别名猜测。`--upstream ID` 可固定规范上游身份。已知上游没有相符 binding 时仍返回该上游及无匹配状态，不扩展到别的账户。

结果包括规范 ID、状态、匹配字段和配置 token；不输出 URL、账户标识、备注或 auth 对象，不解密凭据。已保存 inline key/env/secret_ref 字符串即使误填到标签中也会遮蔽；规范 ID 被遮蔽时必须复核。唯一结果只说明身份唯一，明确保留 `readiness=not-checked`。禁用、草稿、归档项均参与歧义；查询不提供可执行编号、不写项目选择、不改配置或任务。后续编号来自原 selection 菜单，生成前继续完整预检；配置变化需重新查询。旧任务继续原快照，不用名称查询重新分配账户。
