# 动画故事创作首版：实现与验收记录

版本：3.0.0.dev7；日期：2026-11-11。此记录区分软件链路和真实内容质量，未训练模型，未认证可量产成片。

## dev7 本轮优化

新增 `animation preview`，从已完成的相邻小样提取独立剪辑，不再临时缩短主制作计划。修剪同步重排独立音轨、字幕和叠加时间，拒绝截断半句；不要求尚未制作的后续镜头配音。小样带 `animation-pilot` 范围，不能用于认证完整故事。真实 Grok 两镜已输出约 6.02 秒修剪版，首镜在 1 秒切走以去掉重复开盖；主 14 秒计划和任务记录不变，剪辑没有新增付费请求。

用户实际观看原 10 秒小样并反馈“角色没有变形、穿模等”“只有环境声音，比如盖子放地上的声音，没有音乐和说话”，后续确认“动作自然，画面干净”。反馈绑定实际观看文件的 SHA-256，分别映射 0–5 秒与 5–10 秒到两个源片的 0–5 秒。共用审核新增可校验的 `mapped_view` 证据，验证观看文件、剪辑配方、源片哈希及时间对应；变速、画面叠加或混音不能冒充原片验收。两段源片适用内容层已依据用户反馈通过；重复开盖保留为剪辑问题，完整故事仍待最终播放验收。

真实素材联调修复了小样与 `animation status` 的缓存判断：此前只比对基础 job 哈希，真实提交还包含画幅和参考图字节，导致可用素材误判为过期。现在复用与运行器共用完整计算，并采用原绑定的提示词字节上限；旧任务的持久化哈希不改变。回归覆盖声音/字幕不重生成、画幅或参考图字节变化失效。

Windows 完整 455 项通过（331.295 秒），本机 WSL Ubuntu 完整 455 项通过（302.792 秒，3 项 Windows 专属测试跳过）。增强缓存用例又分别通过 Windows/Linux 动画 20 项。旧提交的 GitHub Linux 测试随后结束，暴露旧剪辑器在变速片段的 FFmpeg 补音阶段超时；本地未复现同一故障。已把旧剪辑器和 v3 时间线的无限补音改为按目标时长有限补音，保留超时诊断，相关 23 项在 Windows 与限制双核的 Ubuntu 上通过；最新远端结果仍以 CI 为准。CI 增加 15 分钟上限和周期堆栈，不能将超时本身当作修复证明。

本地技能已更新为 dev7，安装前后 4 个配置/加密凭据文件哈希全部相同。无可选声音模型下载。开发继续使用 main；测试项目、用户图片、配置和凭据不进入公开包。

## 真实测试与优化

12 片参考（合计 231.219 秒）已通过新导入入口，登记为 art 用途，未自动当成 12 条已理解的剧情。此前 120 张概览与 40 张细节帧研究仍属静帧证据，不能证明连续运动或听到的对白。

本机只读模型查询：Aivalux 对应配置能看到 `muse-video`、`gpt-image-2.6`；GateAI 当前该账号目录没有看到 `gpt-image-2.6`。目录可见不是生成认证。

以下为 dev6 阶段的 5 次图片请求和 3 次视频请求记录；dev7 的后续尝试以本地项目账本为准：

- 早期两张图把错误的“宽嘴”描述扩展成鸭嘴。用户提供权威人物三视图后，将主题修正为水豚，版本升级为 1.1.0，错误候选保留并标为不适合作为水豚身份。
- 改用用户图裁出的两张正面作为身份依据。受图片 binding 的单参考限制，本地组合指导图；生成的视频首帧仍是单一场景。
- 修正后首张图保留水豚鼻吻部、小嘴、橙子头饰及对应服饰，可用作试镜首帧；不声称几何完全一致。
- 第二张图最初泄露了后续才出现的饼干，且把圆盒变成方盒。把 payoff 道具单独注册，只加入可见镜头；锁定圆盒形状并加入场景/道具指导，再生成的第二张关键帧已按单画面检查。
- 首次视频联调先纠正了两项本地编排问题：不把“已有上游历史质量证据”误当成首次实验的前置条件；默认只发已审核首帧，额外指导图需明确启用且符合 binding 上限。两项本地预检查失败均未发送视频创建。
- 真正发出的 Muse 请求未返回可确认的协议任务 ID。任务 `job-001`、attempt `26848c418c7f42f9a691e1b9dade8e70` 保持 `submission_unknown`；未重发、未切换原任务上游、未伪造失败或成功。没有再向 Muse 创建请求。
- 用户随后明确要求“可以换成 grok 视频模型，不用 muse”。据此在独立 Grok 小样项目记录新的授权，复用原两张已审核首帧，原 Muse 项目与账本完整保留。选用此前实际跑通过且返回模型无异名的 `grok-video--rapidapi`，未选择曾报告模型异名的通道。
- 两段 Grok 任务均完成，创建和返回模型都为 `grok-imagine-video-1.5`。每段实际 5.041667 秒、720×1280、24 fps，含音轨；在共用时间线上各保留 5 秒，导出 `grok-capybara-pilot.mp4`，实际容器时长 10.021333 秒。技术解码通过，上游返回模型名不是对其内部实现的独立证明。
- 对两段做静帧检查，水豚口鼻、角色配饰与服装得到保留。抽帧可见首镜已举起盒盖、第二镜也开盖，存在衔接修剪点；静帧不用于认证连续动作或声音。草稿和源视频审核模板均保留为待审核，没有以 API 成功替代内容通过，也没有扩展生成第 3 个镜头。

全部 8 次请求均缺少已核实价格/实际账单；Muse 请求是否计费也未知。当前已有可播放的 10 秒真实动画草稿，尚未通过完整的动作、听音和剧情验收，不把它作为完成故事或量产证明。

本地真实联调项目为 `projects/animation-capybara-pilot-20261111`。保存用户图裁剪来源、已选两张首帧、三次图片尝试、生成账本和未知视频任务。错误鸭子候选留在 `projects/animation-dev6-reaction`，不作为当前角色身份。两个项目均被 Git 忽略。

Grok 小样项目为 `projects/animation-capybara-grok-pilot-20261111`，同样被 Git 忽略。`model-switch.json` 记录用户主动切换的依据；两次创建有已知任务 ID、源 MP4 与哈希，主制作计划保留 14 秒完整故事并通过校验。10 秒预览的剪辑配方另存为 `timeline.pilot.json` 与 `pilot-render-context.json`，只包含前两镜，结尾的分享饼干反转尚未制作。

## 软件验证

新增动画测试覆盖两套主题 × 三种故事、剧情要点与因果映射、来源用途、证据方法、真实本地 Unicode 视频导入、哈希变化、首帧失效、单图片指导、独立系列、声音缓存与音轨、实际 FFmpeg 剪辑、未知提交不重发、实际成片审核与失败优先。

运行 `python -m unittest discover -s tests -q`：首轮 450 项全部通过，耗时 320.507 秒，其中新增动画测试 20 项。GitHub Windows 环境随后发现临时目录的 8.3 短路径与规范长路径不一致，已在参考导入入口统一解析项目根目录；原 Unicode 导入测试同时覆盖等价路径写法。修复后的针对性 20 项全部通过，完整回归 450 项再次全部通过，耗时 325.269 秒。GitHub 两个操作系统的运行状态以最终提交的 CI 页面为准。

## 尚需内容实测的里程碑

M1：离线创作与可执行计划链路可用。M4：第二主题的离线可替换性通过。M2：用户改用 Grok 后已有真实 10 秒视频草稿，连续播放、听音和内容验收仍待完成。M3：无对白反应、对白反转和接触照顾三类已覆盖离线计划与合成媒体测试，尚无三类真实内容验收，不宣称可量产。

Muse 原请求的恢复需先核实该原始 attempt 的供应商记录；只有拿到真实任务 ID 或明确“未受理/未创建”的证据后，才能走原任务恢复/核实流程。普通“查不到”不足以允许重发。本次 Grok 创建来自用户明确的新指令，不是将未知 Muse 请求自动判成失败。新增真人剧情可直接进入新模块，不需要逐帧替换真人，也不固定为这套水豚角色。
