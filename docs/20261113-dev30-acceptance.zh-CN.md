## 实际入口与行为

项目与任务面板新增两个明确动作，调用已有共享核心，未另建生成、剪辑或交付实现。

| 入口 | 实际行为 |
| --- | --- |
| 渲染当前时间线 | 视频、混合视频及仅剪辑项目使用；在后台重新读取并校验已保存计划和任务状态，调用本机 FFmpeg 渲染 deliverables/preview.mp4、SRT 与渲染清单 |
| 导出交付清单 | 调用 production.delivery，重新读取项目状态、审核与文件哈希；视频导出 preview.delivery.json，纯图/GIF 继续导出各自的集合交付清单 |
| 完成信息 | 通过 Tk 主线程队列轮询更新；刷新步骤、审核与统计后，显示输出路径、完整解码结果和实际审核状态 |
| 失败与关闭 | 同一面板正在操作时禁用两个动作，重复点击不重复执行；失败显示实际错误并恢复按钮；关闭面板取消界面定时回调，已启动的本地操作继续完成 |

布局检查发现旧的顶层 pack 顺序会让展开的内容区域占满窗口，导致后续工具栏被挤出默认 1040×760 窗口。现将状态与各工具栏集中到底部预留区域，再让 Notebook 使用剩余空间。六类项目的可见性测试在真实映射但完全透明的窗口中检查全部按钮尺寸、映射状态和窗口边界；只构造控件的离屏 smoke 不能替代这项检查。修正前的构建已被最终构建替换，不作为发布依据。

保存创作层和执行本地动作仍分别触发。尚未保存的表单不进入渲染；面板打开后刚保存的时间线会在执行时读取。纯图、原生 GIF 和本地 GIF 集合没有视频时间线，不显示视频渲染按钮，直接服务调用也拒绝这些分支的误用。

渲染和导出均不读取供应商配置、不调用模型客户端、不创建任务、不上传或发布。旧 task ID、原路线快照、候选、账本和创作层保留。技术解码 pass 不等于内容通过；实际交付状态继续由现有审核证据决定，可以保持 review_pending。
