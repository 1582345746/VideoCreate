## 实际功能

每类项目面板新增“制作流程与检查点”，与 CLI production policy-show/policy-preview/policy-save 共用离线服务。可选逐步核对所有适用策划阶段，或按现有授权推进、保留指定主题/大纲/剧本/角色/分镜/参考检查点。表格区分实际完成状态与推进策略：略过的计划保持未核对，不伪装成已完成；不适用阶段保留跳过原因。原有无模型任务的本地剪辑/GIF 分支补齐生成阶段跳过理由。

预览列出原策略和新策略各自的下一步、实际阶段、现有任务与预算。source/preview token 绑定项目路径、计划、任务/账本、流程记录、素材/审核派生状态，以及模式、检查点和理由；保存时在项目锁内重验。计划/任务/策略变更、不同理由或两次竞争保存拒绝旧预览。读和预览不写项目，保存只更新 production/stages.json；没有设置变化不追加历史。

可选中任意适用策划阶段查看真实当前内容，通过与“继续制作”共用的检查表单修改原计划或填写核对理由。记录仅批准该版本计划，不批准媒体。计划变更后原检查点可过期，后续继续制作重新定位到指定待核对阶段。图片/GIF、仅剪辑、混合视频及普通视频继续使用各自阶段和来源服务。

改动后的策略记录为 schema_version=2，保留 v1 的检查结论、历史和扩展字段；读取、预览和无变化保存不强制升级。旧版只接受 v1 时明确拒绝新版记录，避免忽略指定检查点。已实际使用本机 dev33 CLI 对独立 v2 合成项目验证拒绝行为，项目文件前后不变。

界面读取、预览与保存放在后台线程，worker 只接收普通值和 queue。编辑控件后旧预览失效；重复点击只执行一次。关闭窗口取消界面回调，已经开始的本地保存事务仍完成。界面不保存另一份任务状态，也不读上游凭据来处理流程策略。

策略用于继续制作的阶段定位，不启动无人值守的执行循环。显式生成与恢复面板仍沿用自身授权、预检、固定原路线和预算规则；策略设置不授予费用权限，不修改限额，不将图片、视频或声音变成已审核。未知提交、坏计划和缺少必须本地来源仍优先处理。
