## 实际验证

新增 [维护验证工具](../tools/verify_web_lifecycle.py) 在新的 F 盘目录运行，使用独立 Python 3.9 环境、中文/空格/`&` 路径、合成配置与不透明凭据哨兵。它核对 wheel/ZIP 哈希、字节数及两包中维护说明的字节，随后执行以下九阶段，每阶段比较全部 13 个合成用户文件的相对路径和 SHA-256：

| 阶段 | 观察 |
| --- | --- |
| dev43 基线 | 普通配置离线校验通过 |
| 升至 dev44 | 版本及普通配置校验通过 |
| 同版本候选强制重装 | 配置、历史、草稿、任务和哨兵全部保留 |
| 回滚 dev43 | 普通配置可读；含 `per_image` 的另一份配置被明确拒绝，原字节不变 |
| 再回 dev44 | 新字段配置可读，不通过删除字段绕过旧版限制 |
| pip 卸载 | 仓库外 import 查询为空，两个 console 入口消失；全部用户文件保留 |
| 无 wheel 的 ZIP | ZIP 自身源码可运行，普通配置可读，包内说明一致；不要求根目录安装器 |
| ZIP 改名隔离 | 只更名本次解压副本，原路径消失；所有程序和用户文件字节保留 |
| wheel 重装 | 普通配置及新字段配置都可读，pip check 通过 |

凭据、旧备份和 Tk 草稿的哨兵不是合法 DPAPI 密文，样片哨兵不是可播放视频；这些结果仅证明安装操作保留字节，不能证明真实凭据解密、真实任务恢复或样片审核通过。测试没有解析真实凭据、连接上游、播放或重新生成媒体。子进程加载已核验的网络阻断模块；connect/connect_ex/sendto/create_connection/getaddrinfo 五个入口均绑定阻断函数，实际外部连接尝试为零。

首轮验证工具把 METADATA 当作只含 LF 的文本，遇到原 dev43 wheel 的 CRLF 时提前拒绝，尚未创建安装夹具。改用标准邮件头解析器后 r2 九阶段通过；随后补五个网络入口的绑定断言，r3 再次通过。首轮失败日志与 r2 成功记录保留。该修正只涉及开发验证工具，不影响候选产品字节。

权威证据：`_local/web-lifecycle-20261114-r3/result.json`、`commands.log`。四入口 Web 实际运行、只读 HTTP/静态资源、同实例复用及升级回滚另由 `_local/web-candidate-install-20261114-lifecycle-r1/result.json` 覆盖。五个 PowerShell 文档代码块另作语法解析，未直接执行指向真实数据的示例。
