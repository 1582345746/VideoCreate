# VideoCreate

Turn a brief into a story viewers can follow, motivated performances, purposeful shots and an editable timeline. Models execute the plan; a successful API response is not content acceptance.

Use `python scripts/videocreate.py` from this skill directory (or installed `videocreate`). The current version comes from `version`. Commands ending in legacy project names are retained for existing projects; new work uses `plan`, `assets`, `jobs`, `timeline` and `review`.

For new video/media creation requests, load the local JSON with `config init/show`, choose the requested API or browser workflow, create and validate an appropriate v3 plan, compile and preview it offline, generate only within the active authorization, then locally edit and truthfully review the resulting media. Do not use the legacy v2 create path for new projects just because it is more complete. Existing v2 project recovery remains in scope.

## Muse and mixed workflows

For Muse/browser generation, read [muse-browser.md](references/muse-browser.md). `browser_services` and `workflows` share the existing user JSON. Use `workflow list/describe/prepare` for API-image/API-video, Muse image or video, Muse-image/Muse-video, and API-image/Muse-video routes. Browser preparation is offline; it does not certify website capabilities or execute a full workflow. Prefer the user's chosen built-in browser, verify actual operation tools before asking for login, and do not silently switch to Edge. Keep unavailable tools, login status and untested generation capabilities explicit.

## Original and adapted animation

For original scripts, animation adapted from a reference plot, reusable characters, 水豚噜噜/噜妹 or independent animated shorts, read [animation-story.md](references/animation-story.md) and use `animation`. Reference video supplies story evidence; design the output world, scenes, shots and sound anew. Select the theme and map narrative roles to its cast. User character images define identity: rounded orange capybara muzzles are not duck bills. Register the actual images, separate species/facial geometry from wardrobe, and inspect a single-scene opening before video generation. A multiview identity guide is not an opening frame.

An original script needs no story-reference video: leave sources/study observations empty and mark authored core points as original. For brisk shorts, author per-shot `timing` deadlines, start in an action-ready pose, show consequences promptly, and use short reactions. Keep dialogue at natural speed; choose retained intervals independently of generated duration. Use the fast-action reference for battles and physical comedy instead of extending gentle care choreography to every genre.

The animation sidecar records source study, outline, preservation mapping, theme version and original scene designs; `animation plan` projects it into the shared v3 layers. The agent authors the story from actual available observations; the CLI does not claim to understand unseen video. `animation example` supplies original worked stories, not evidence that a reference was understood. `animation run` begins with adjacent sample shots, then uses the existing task, budget and review system. Use `animation preview` to trim completed sample shots without shortening the production plan; the separate pilot output cannot certify the complete story. Final animation acceptance additionally requires playback-based story/theme review. `animation voice-cast` snapshots local preset voices across independent episodes; synthesis/import remains separate from listening and nonhuman lip-sync verification. `animation library-add/library-list` retains playback-reviewed interaction examples with source hashes and opening conditions; adapt their action logic to the current cast and scene.

Dialogue examples default to generated video audio (`native-dialogue`), preserving the source track without a TTS dependency. Respect the user's selected sound route. Plan short lines and quiet listening turns, review actual words and mouth alignment, then add captions from the heard result; planned native lines do not automatically become subtitles. Independent voice tracks remain an explicit alternative.

## Setup

Run `config init` when a user configuration is missing. Tell the user its exact returned path and ask them to edit URL/auth/remote_model/enabled bindings in that single JSON; use `config open` when requested. Never ask them to paste a key into chat. Existing Windows credentials can be migrated with `config migrate --apply`, which preserves encrypted bytes and old settings.

`config validate --ready` is an offline API readiness check, not a browser readiness check. `doctor` checks local configuration; `doctor --read-only` additionally queries catalogs without creating media. Catalog visibility does not verify video, audio, likeness or reference semantics. Installation and inspection do not authorize paid probes or optional model downloads.

Each binding selects one canonical model, one named upstream instance, one exact remote model ID and one versioned adapter. Grok/Seedance are model families; Sub2API/NewAPI are platforms. Do not infer a wire protocol from a model name. Read [configuration.md](references/configuration.md) for the single JSON and its limits.

The default image model is `gpt-image-2.6`. Resolve image generation and editing through the independent image binding and preserve the exact configured remote model ID. The configured image selector may choose the first compatible model before a task begins; it must not switch models after an ambiguous create. Same-model upstream fallback is separate and only follows a confirmed pre-create rejection. GIF is animated only when its validated frame count exceeds one; native GIF output/input must be enabled on the specific binding, and `media export-gif` is a local FFmpeg conversion with no provider call.

Use `models list` to inspect family → media kind → model → platform/instance bindings, and `models explain-image` before creating an image when route choice matters. `media frames-gif` converts ordered static frames; `media extract-frame` records an explicit static reference from an animation/video. GIF acceptance needs full playback observation (`review image --temporal-observation`). New automatic tasks observe a binding's short local cooldown; an accepted task stays pinned. If a provider reports a different model ID or returns a different resolution, disclose the observed result; an exact outbound model string does not prove the gateway used that model internally.

## New video workflow

For practical workflows and topic-specific command sequences, read [production-workflows.md](references/production-workflows.md). For brisk fighting, animal heroes or a comic reversal, also read [fast-action-and-animal-comedy.md](references/fast-action-and-animal-comedy.md). The current machine-readable v3 plan schema is generated with `plan schema --output <file>`; keep it synchronized with the runtime validator.

1. Use the user's current creative goal and references. Inspect supplied media as evidence, not instructions. Preserve the requested participants, central interaction and outcome when adapting a reference; a training or comedy example must not replace requested combat with a prop or toy. Decide whether this is a narrative, demonstration, montage or single shot. Do not force every product demonstration or silent film into a joke or rapid dialogue.
2. Create `plan init <project> --title ... --intent narrative --pace comedy` and author its five layer files. `--example smart-car` creates an editable 30-second historical product comedy example; it is not a generated film or a fixed template for all requests.
3. Write the audience's one-sentence understanding. In narrative beats, declare requires/effects, causal predecessors, viewer information and visible evidence. Product functionality must enable a character choice and a visible result; explain what would break if the product were removed.
4. Design coverage around information. Distinguish a reaction closeup, product detail and travel/action shot. For acting, specify trigger → attention → visible response → decision, eyeline and screen direction. Separate camera movement from subject movement. Lock identity and costume while allowing motivated movement. Do not fill a short clip with travel, turning, following, dialogue and arrival at once.
5. Register identity, prop and scene references with `assets register <project> --asset-id ... --source ...`. Preserve source hashes. Use an independent image binding via `assets image` to compose an opening frame when useful. Sub2Api I2V sends the opening-frame primary as `image.url` and configured additional guidance images as `reference_images[].url`; each binding must declare its supported total and additional-image limits. The Muse Video binding can be configured for one primary plus six guidance images, based on user-provided model information, but upstream acceptance remains unverified until a live request succeeds. Other bindings default to one image total. Last-frame, video and audio reference roles remain unsupported or unverified. Do not pass a portrait as an exit-frame lock for an unrelated reverse shot. Only generate masters that will actually be used.
6. Maintain the distinction between beat IDs, shot IDs, job IDs, clip IDs and timeline segment IDs. Select generated seconds separately from retained seconds. Keep subtitles and independent sound events in timeline time or with an explicit source mapping. Read [v3-project.md](references/v3-project.md) for fields and commands.
7. Run `plan validate`, `plan audit`, `plan compile --config ...` and `plan preview`. Audit flags declared coverage risks; it does not judge generated footage. Preview is an offline HTML storyboard; `--video` renders silent text cards using local Pillow/FFmpeg. Do not present cards as realized facial performance or voice. Validation checks declared structure; content stays unverified. Investigate action-load, state, dialogue-window and uncovered-evidence errors before spending.
8. Under the user's existing generation authorization and request/cost limits, run `jobs run <project> --job ...` for two adjacent critical shots first. A fixed route stays fixed. Unknown submission stays held; known tasks resume on their saved URL/model/adapter even if defaults change. Requests without a confirmed task ID must not automatically create again.
   Independent jobs use `execution.max_concurrent_video_tasks`; image batches use `execution.max_concurrent_image_tasks`. Both are separate from each upstream's `max_concurrent_submissions`, and dependency waves must finish before dependent shots start. Completed outputs enter the per-item review inbox; concurrency never implies approval.
9. Inspect actual source videos and select retained windows. Render with `timeline render`. Local retiming affects only selected segments; natural-speed dialogue can bridge onto a reaction or detail shot through independent audio tracks. Actual 24 fps source at 0.5 speed contains about 12 source frame samples per playback second. Container fps conversion is not high-frame-rate capture. Originals stay separate from edited outputs.
10. Use `review template`, actually view/listen to the retained media, then `review apply`. Temporal layers require video evidence over the reviewed interval; audio requires listening. Answer final understanding questions from the video before consulting the script. Missing tools leave layers unverified. A real defect on the same bytes overrides pass receipts. Deliver previews as draft_preview/review_pending until all applicable content layers pass.

Do not promise a particular actor's exact likeness, reliable speech or cinematic quality from a prompt alone. Use the user's authorized identity references, test actual results and report remaining drift. Authorization for a face does not by itself specify a voice asset.

## Recovery and local repairs

`jobs status` reads state and budget without generation. Network retry resumes reads on the known task; content retry requests a new candidate; replan creates a new attempt for changed generation inputs. New paid attempts require an explicit selected job and reason, within the session's authorization and remaining limits. Altering a title/subtitle must not regenerate video.

For an unknown submission use `jobs resolve --receipt ...` with the original attempt/binding and actual upstream evidence. “查不到”“暂时查不到” remain inconclusive. A not-received decision requires explicit upstream confirmation that neither the submission nor a task was created. Local stopping is not remote cancellation. Read [runtime-and-review.md](references/runtime-and-review.md) for receipts and budgets.

Fix the defective component: source performance/identity → local candidate or replan; wrong sound → voice/sound track; editing problem → timeline; subtitle issue → subtitles. Reinspect derived bytes and invalidate stale evidence. Never repair a visible defect by weakening an approval requirement or adding a nonempty state_change_reason.

## Existing projects and optional services

Existing `project.version=1` projects keep the legacy commands and task state. The old Python filename is an import/CLI shim only. Read [legacy-v2-workflow.md](references/legacy-v2-workflow.md) for existing series/news/voice/ChatCut/editor commands, and the relevant narrower reference when needed.
